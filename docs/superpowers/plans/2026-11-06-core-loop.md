# 《回廊：借来的明天》核心体验与团队分工计划

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task after team review. Checklist items describe planned work, not completed features.

**Goal:** 保留队长项目，让玩家通过证据操作、换相回程和再次接案，理解“回到同一选择，但已经知道代价”。

**Architecture:** 沿用 game.gd 状态机、interface.gd 立即模式 UI、station.gd 网格与程序化布景。不新建通用谜题框架，不改变 profile.gd 存档结构。先完成一个可验证的核心段落，再考虑内容扩展。

**Tech Stack:** Godot 4.3 / GDScript / 现有 Python 本机后端。

**Spec:** 本次对话批准的三个方向：接案反转、1～2处现有谜题交互升级、探索回路与关键陈设。本文是执行前的范围确认稿，不是已完成报告。

## 全局约束

- 只围绕 captain-lofrmin；不恢复、不修 jam48 或 cycle。
- 不升级引擎；不动六道谜题的核心事实与既有章节编号。
- A-42 是授权，X-71 是交易；不能把两个编号混用。
- 第一次同门事件：V-17 / #043；时间谜题仍是晨暮 1:1000。
- 不增加追债人数、不新增完整经济系统、不做几何圆形地图重建。
- 未经决定不覆盖队长远端工程；合并前必须确认本地副本是否最新。
- 不把真实存档当测试夹具，不把 SQLite、玩家标识、密钥放进交付材料。
- 测试与视觉验收均要通过，不能只以可编译作为完成。

## Review Focus

1. 旧存档章节仍正确；新增临时交互不污染永久证据。
2. 第一次看到授权不能提前泄露全部反转；再次返回必须有可见变化。
3. 键盘1/2/3与鼠标不能绕过新谜题；错误输入不能损坏进度。
4. 晨/暮场景、碰撞、A*、小地图使用同一套道路事实。
5. 精修资产不能遮挡关键文字、阻止E交互、挡住通路或显著破坏帧率。

## Task 1：同一张桌子，不同的选择

**Files:** game.gd（handle_action/interact/update_witness/reset_lap）；station.gd（fixture和调查台显示）；interface.gd（调查台）；新增 tests/core_loop_test.gd。

**Interfaces:** game.gd 提供 `audit_status_text() -> String`，由当前 chapter/case_accepted/evidence 派生，不增加存档字段；station.gd 提供 `update_audit_status(text: String) -> void` 仅显示状态。

- [ ] 先测试：chapter=1、case_accepted=false 时显示“待复核”；确认接案后显示“已复核”；reset_lap后恢复待复核，已入匣证据按原规则保留。
- [ ] 确认测试因接口不存在而失败，再实现最小状态显示。
- [ ] 调查台增加电脑支架/键盘轮廓、授权纸张、凭证夹；纸面与屏幕沿用现有角色事实，不生成乱码文字。
- [ ] 原稿与用户文案未确认前，使用既有 A-42 文本，不自编新的关键因果。
- [ ] 运行断言测试；截图比对签收前/签收后/重启后三种状态；测试不能访问真实用户存档或后端。
- [ ] 队长确认剧情无矛盾；再合入这一项。

## Task 2：把“同一扇门”变成证据对齐操作

**Files:** game.gd（answer及audit键盘入口）；interface.gd（draw_evidence/button_at）；tests/core_loop_test.gd；谜题答案.md。

**Interfaces:** `alignment_fields: Array[String]` 只保留当前终端选择；`submit_alignment(fields: Array[String]) -> void` 校验 mode==audit、chapter==0、证据齐全、选择包含 device 和 alarm 后，调用共用章节推进逻辑。时间字段 clock 不是跨区事件身份。

- [ ] 先测试：缺证据不能提交；选择clock不能过关；仅device不能过关；device+alarm正确进入既有下一章；其他章节路径不变。
- [ ] 旧 `answer(1)` 和键盘数字路径在chapter=0不能跳过配对，写测试锁住。
- [ ] 用点击选字段＋提交做最小交互；不首发复杂拖拽系统。
- [ ] 晨暮记录同时可见，选中V-17与#043时提供连线/高亮，错误时提示比较事件身份而非直接报答案。
- [ ] 测试、实机鼠标/键盘验收通过后更新谜题说明。

第二项谜题（同步时间轴）不属于首批承诺；第一项体验有效且稳定后再做。

## 模型样件规范（先试一个）

- 先做静态调查台道具；追债人生成样件为可选，不阻塞核心玩法。
- 与现有晨青/暮暖、旧式工业空间站的材质风格一致。
- 电脑外壳、可变屏幕、纸张分开；关键文字由排版/界面制作，不让生成模型决定。
- 交付GLB、预览、尺寸说明、工具和来源记录；不要只交网页预览链接。
- 人物须说明是否带骨骼、是否有可用idle/walk；没有就按静态外观样件验收，不宣称可直接接动画。
- 先在同一摄像机距离检查比例、背面、材质、碰撞与帧率，过关后才扩量。
- 混元账号、费用/额度及生成素材的使用条件由账号持有人确认；密钥只在本机配置。

## 完成门槛与延后路线

首批完成不是“代码能运行”，而是陌生试玩者能说明：确认接案让谁付出代价、复位留下了什么、为什么第二次会改变选择；并能完成一次证据对齐和回程。

优先拓展顺序：
1. 同步时间轴交互（复用现有1:1000事实）；E-7通电/接线反馈。
2. 追债人记忆的可见反馈（常用门被巡查），保留预警和可逃路线。
3. 晨暮环境叙事的成对细节与纸面证据。
4. 经试玩确认确实需要后，终章限定第二追债人；先测两门都被堵时的可解性。

延期：无限AI剧情、多分支结局、整图重建、新骨骼动画系统、自由物理搬物、大量随机谜题。

扩展必须满足：主线可完成、当前发行包可回退、还有完整回归与录屏时间。任一不满足则不加。
