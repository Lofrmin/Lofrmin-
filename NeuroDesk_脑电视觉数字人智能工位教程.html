问题 实际情况 建议的说法
EEG 是你本人的脑电吗？ 不是。它是公开数据集的回放，和你此刻的状态无关 「EEG 通道用公开数据集回放，验证信号处理链路；数据接口和真实头环（TGAM / Muse 等）一致，换上硬件就能直接用」

摄像头用电脑的还是 ESP32 的？

推荐方案 A：电脑摄像头做感知，ESP32 做执行端。 理由：

  • MediaPipe 在浏览器里直接读 getUserMedia，延迟最低、帧率稳定在 30 fps 左右。
  • ESP32-S3 + OV2640 走 MJPEG 推流，QVGA 下也只有十几到二十几帧，还会多出 Wi-Fi 延迟。浏览器读跨域图像流时 canvas 会被「污染」，必须在 ESP32 的 HTTP 服务里加 Access-Control-Allow-Origin 头才能交给 MediaPipe。
  • 让 ESP32 做「工位」更符合真实产品形态：感知在 PC，执行在边缘设备。

方案 B（进阶，放到最后）：ESP32-S3 摄像头推流 → 浏览器 MediaPipe。等主流程全部跑通后再当亮点加。

1准备 EEG 数据

1.1 原理：脑电的频段和「专注 / 困倦」

EEG 是头皮上 μV 级的电位波动。工程上最常用的特征是频段功率：

频段 频率 常见关联
θ（theta） 4–8 Hz 困倦、浅睡；额区 θ 也会随工作记忆负荷上升
α（alpha） 8–13 Hz 放松、闭眼静息时最明显（枕区），集中注意时会被抑制
β（beta） 13–30 Hz 主动思考、警觉

两个经典指数：

  • 投入度（Engagement） E = β / (α + θ)，出自 Pope 等人 1995 年的 NASA 研究。
  • 困倦度（Drowsiness） D = (θ + α) / (α + β)，属于驾驶疲劳文献里常用的几种频段比值之一（如 Jap 等人 2009 年的研究）。

原理这两个指数高度相关，本质上都在描述「放松 ↔ 投入」这一条轴。这也是为什么「疲劳」主要靠摄像头判断，EEG 只做辅助。

1.2 数据集：PhysioNet EEGMAT

「EEG During Mental Arithmetic Tasks」：36 名受试者，19 导，500 Hz。每人两个文件：SubjectXX_1.edf 是任务前静息（约 3 分钟），SubjectXX_2.edf 是心算任务（约 1 分钟）。

下载地址：https://physionet.org/content/eegmat/1.0.0/，先挑 2–3 个受试者的 _1.edf / _2.edf 放进 data_prep/raw/。

1.3 预处理并导出 JSON

data_prep/prep_eeg.py：

import json
from pathlib import Path

import mne
import numpy as np

RAW = Path(__file__).parent / "raw"
OUT = Path(__file__).parents[1] / "web/public/eeg/session.json"
PICKS = ["Fp1", "Fz", "Cz", "Pz", "O1"]  # 额-中央-顶-枕，各取一个，前端画 5 条
FS = 128


def load(path):
    raw = mne.io.read_raw_edf(path, preload=True, verbose="error")
    raw.rename_channels(lambda n: n.replace("EEG ", "").replace("-A1", "").replace("-A2", "").strip())
    raw.pick(PICKS)
    raw.notch_filter(50, verbose="error")          # 工频
    raw.filter(1.0, 40.0, verbose="error")         # 去基线漂移和高频噪声
    raw.resample(FS, verbose="error")              # 500 → 128 Hz，JSON 体积降到 1/4
    return raw.get_data() * 1e6                    # V → μV


def main(subject="Subject00"):
    rest = load(RAW / f"{subject}_1.edf")
    task = load(RAW / f"{subject}_2.edf")
    data = np.concatenate([rest, task], axis=1)
    marks = [
        {"t": 0.0, "label": "静息（任务前）"},
        {"t": rest.shape[1] / FS, "label": "心算任务"},
    ]
    OUT.parent.mkdir(parents=True, exist_ok=True)
    OUT.write_text(json.dumps({
        "fs": FS,
        "channels": PICKS,
        "marks": marks,
        "data": np.round(data, 1).tolist(),
    }), encoding="utf-8")
    print(f"{subject}: {data.shape[1] / FS:.0f}s, {OUT.stat().st_size / 1e6:.1f} MB")


if __name__ == "__main__":
    main()

from scipy.signal import welch
from prep_eeg import load, RAW, FS

BANDS = {"theta": (4, 8), "alpha": (8, 13), "beta": (13, 30)}


def band_power(x):
    f, p = welch(x, fs=FS, nperseg=FS * 2, axis=-1)
    return {k: np.trapezoid(p[..., (f >= lo) & (f < hi)], f[(f >= lo) & (f < hi)], axis=-1).mean()

2浏览器里回放 EEG 并实时算指数

2.1 原理：回放 = 用时钟推进游标

数据是离线的，但只要「每一帧根据真实流逝的时间推进读取位置」，就和实时采集没有区别：

  • 游标 cursor = (now - t0) × fs × speed，读到末尾就从头循环。
  • 屏幕上画最近 windowSec 秒的波形，形成滚动效果。
  • 每 0.5 秒取最近 256 个点（128 Hz 下是 2 秒），加 Hann 窗做 FFT，得到频谱。频率分辨率 = fs / N = 0.5 Hz。

Hann 窗的作用：截断出来的一段信号两端不连续，直接做 FFT 会产生「频谱泄漏」，能量会糊到相邻频段上。乘上两端趋于 0 的窗函数可以大幅减轻这种泄漏。

2.2 回放器 src/eeg/player.js

export class EEGPlayer {
  constructor(canvas, session, { windowSec = 6, speed = 1 } = {}) {
    Object.assign(this, { canvas, ctx: canvas.getContext('2d'), s: session, windowSec, speed });
    this.n = session.data[0].length;
    this.t0 = performance.now();
    this.offset = 0;
  }

  get cursor() {
    const elapsed = (performance.now() - this.t0) / 1000 * this.speed;
    return Math.floor(this.offset + elapsed * this.s.fs) % this.n;
  }

  seek(sec) {
    this.offset = Math.floor(sec * this.s.fs);
    this.t0 = performance.now();
  }

  latest(len) {
    const end = this.cursor;
    return this.s.data.map(ch => {
      const out = new Float32Array(len);
      for (let i = 0; i < len; i++) out[i] = ch[(end - len + i + this.n) % this.n];
      return out;
    });
  }

  currentMark() {
    const t = this.cursor / this.s.fs;
    return this.s.marks.filter(m => m.t <= t).at(-1)?.label ?? '';
  }

  draw() {
    const { ctx, canvas } = this;
    const w = canvas.width, h = canvas.height;
    const rows = this.latest(this.windowSec * this.s.fs);
    const rowH = h / rows.length;
    ctx.clearRect(0, 0, w, h);
    rows.forEach((sig, r) => {
      const mid = rowH * (r + 0.5);
      ctx.strokeStyle = `hsl(${190 + r * 28} 90% 60%)`;
      ctx.lineWidth = 1.2;
      ctx.beginPath();
      for (let i = 0; i < sig.length; i++) {
        const x = i / sig.length * w;
        const y = mid - sig[i] * (rowH / 120);   // 约 ±60 μV 占满一行
        i ? ctx.lineTo(x, y) : ctx.moveTo(x, y);
      }
      ctx.stroke();
      ctx.fillStyle = '#9aa4b2';
      ctx.fillText(this.s.channels[r], 6, mid - rowH * 0.3);
    });
  }
}

2.3 FFT 和频段指数 src/eeg/bands.js

// 原地 radix-2 FFT，长度必须是 2 的幂
function fft(re, im) {
  const n = re.length;
  for (let i = 1, j = 0; i < n; i++) {
    let bit = n >> 1;
    for (; j & bit; bit >>= 1) j ^= bit;
    j ^= bit;
    if (i < j) { [re[i], re[j]] = [re[j], re[i]]; [im[i], im[j]] = [im[j], im[i]]; }
  }
  for (let len = 2; len <= n; len <<= 1) {
    const ang = -2 * Math.PI / len;
    for (let i = 0; i < n; i += len) {
      for (let k = 0; k < len / 2; k++) {
        const wr = Math.cos(ang * k), wi = Math.sin(ang * k);
        const a = i + k, b = a + len / 2;
        const tr = re[b] * wr - im[b] * wi, ti = re[b] * wi + im[b] * wr;
        re[b] = re[a] - tr; im[b] = im[a] - ti;
        re[a] += tr; im[a] += ti;
      }
    }
  }
}

const BANDS = { theta: [4, 8], alpha: [8, 13], beta: [13, 30] };

export function bandPowers(sig, fs) {
  const n = sig.length;
  const mean = sig.reduce((a, b) => a + b, 0) / n;
  const re = new Float32Array(n), im = new Float32Array(n);
  for (let i = 0; i < n; i++) re[i] = (sig[i] - mean) * (0.5 - 0.5 * Math.cos(2 * Math.PI * i / (n - 1)));
  fft(re, im);
  const out = {};
  for (const [k, [lo, hi]] of Object.entries(BANDS)) {
    let s = 0;
    for (let b = Math.ceil(lo * n / fs); b < hi * n / fs; b++) s += re[b] ** 2 + im[b] ** 2;
    out[k] = s;
  }
  return out;
}

const sigmoid = z => 100 / (1 + Math.exp(-z));

// 前 baselineSec 秒当个人基线，之后用 z 分数映射到 0–100
export class EEGIndex {
  constructor(baselineSec = 20) { this.need = baselineSec * 2; this.E = []; this.D = []; }

  update(channels, fs) {
    const avg = { theta: 0, alpha: 0, beta: 0 };
    channels.forEach(ch => { const p = bandPowers(ch, fs); for (const k in avg) avg[k] += p[k] / channels.length; });
    const e = avg.beta / (avg.alpha + avg.theta);
    const d = (avg.theta + avg.alpha) / (avg.alpha + avg.beta);
    if (this.E.length < this.need) { this.E.push(e); this.D.push(d); }
    const z = (v, arr) => {
      const m = arr.reduce((a, b) => a + b, 0) / arr.length;
      const sd = Math.sqrt(arr.reduce((a, b) => a + (b - m) ** 2, 0) / arr.length) || 1e-6;
      return (v - m) / sd;
    };
    return { bands: avg, engagement: sigmoid(z(e, this.E)), drowsiness: sigmoid(z(d, this.D)), calibrating: this.E.length < this.need };
  }
}

原理为什么要 z 分数：不同人、不同电极的绝对功率可以差好几倍，绝对阈值没有意义。拿「自己前 20 秒」当参照，只看「相对自己高了还是低了」。sigmoid 把 z 压到 0–100：z=0 对应 50 分，z=±2 大约对应 88 / 12 分。

3摄像头 + MediaPipe：眨眼、PERCLOS、哈欠、转头

3.1 原理：FaceLandmarker 输出什么

每一帧输出三样东西：

  1. 478 个 3D 特征点（归一化坐标），可以自己算 EAR（眼睛纵横比）。
  2. 52 个 blendshape 分数（0–1），比如 eyeBlinkLeft、jawOpen、browDownLeft、mouthSmileLeft。这就是现成的「表情线索」，不用自己训练模型。
  3. 面部变换矩阵（4×4），可以从中解出头部的 yaw（左右转）和 pitch（抬头 / 低头）。

基于这些可以算出的疲劳 / 分心特征：

特征 定义 经验参考
眨眼频率 每分钟完整「闭→睁」的次数 静息时大约 15–20 次/分钟；盯屏幕时会明显减少，疲劳时增多或变慢
PERCLOS 一段时间内「闭眼」帧所占比例 驾驶疲劳研究中最常用的指标，> 0.15 通常视为疲劳
长闭眼 单次闭眼 > 0.5 s 微睡眠的信号
哈欠 jawOpen > 0.6 持续 > 1.2 s
视线偏离 |yaw| > 25° 或低头 pitch < -20° 看手机、转头聊天

原理用 EAR 也行：EAR = (|p2-p6| + |p3-p5|) / (2|p1-p4|)。MediaPipe 左眼常用点位是 33、160、158、133、153、144。blendshape 的好处是已经帮你做了归一化，而且对头部转动更稳。

3.3 特征计算（下半部分）

const bs = (cats, name) => cats.find(c => c.categoryName === name)?.score ?? 0;

export class FaceFeatures {
  constructor() {
    this.closed = false; this.closeStart = 0;
    this.blinks = []; this.longCloses = []; this.yawns = [];
    this.closedLog = [];               // [时间戳, 是否闭眼]，用于 PERCLOS
    this.jawStart = 0; this.yawnLatched = false;
    this.lastSeen = 0; this.pose = { yaw: 0, pitch: 0 }; this.cue = { frown: 0, smile: 0 };
    this.thr = { close: 0.5, open: 0.35 };
  }

  update(res, now = performance.now()) {
    const cats = res.faceBlendshapes?.[0]?.categories;
    if (!cats) return;
    this.lastSeen = now;

    // 眨眼：迟滞阈值，避免在阈值附近来回抖动导致重复计数
    const blink = (bs(cats, 'eyeBlinkLeft') + bs(cats, 'eyeBlinkRight')) / 2;
    if (!this.closed && blink > this.thr.close) { this.closed = true; this.closeStart = now; }
    else if (this.closed && blink < this.thr.open) {
      this.closed = false;
      const dur = now - this.closeStart;
      if (dur < 500) this.blinks.push(now); else this.longCloses.push(now);
    }
    this.closedLog.push([now, this.closed]);

    // 哈欠：张嘴持续超过 1.2 秒，闭嘴后才允许下一次计数
    const jaw = bs(cats, 'jawOpen');
    if (jaw > 0.6) {
      this.jawStart ||= now;
      if (!this.yawnLatched && now - this.jawStart > 1200) { this.yawns.push(now); this.yawnLatched = true; }
    } else { this.jawStart = 0; this.yawnLatched = false; }

    // 头部姿态：变换矩阵是列主序的 4×4
    const m = res.facialTransformationMatrixes?.[0]?.data;
    if (m) {
      const deg = 180 / Math.PI;
      this.pose = { yaw: Math.atan2(m[8], m[10]) * deg, pitch: Math.asin(-m[9]) * deg };
    }

    this.cue = {
      frown: (bs(cats, 'browDownLeft') + bs(cats, 'browDownRight')) / 2,
      smile: (bs(cats, 'mouthSmileLeft') + bs(cats, 'mouthSmileRight')) / 2,
    };

    const cut = now - 60_000;
    this.blinks = this.blinks.filter(t => t > cut);
    this.longCloses = this.longCloses.filter(t => t > cut);
    this.yawns = this.yawns.filter(t => t > now - 300_000);
    while (this.closedLog.length && this.closedLog[0][0] < cut) this.closedLog.shift();
  }

  snapshot(now = performance.now()) {
    const closedFrames = this.closedLog.filter(([, c]) => c).length;
    return {
      present: now - this.lastSeen < 1500,
      blinkPerMin: this.blinks.length,           // 跑满 60 秒之后才准确
      perclos: this.closedLog.length ? closedFrames / this.closedLog.length : 0,
      longCloses: this.longCloses.length,
      yawns5min: this.yawns.length,
      ...this.pose, ...this.cue,
    };
  }
}

注意yaw / pitch 的正负号取决于坐标系和摄像头镜像。写完之后亲自测一遍：抬头、低头、左转、右转，各看一次数值的正负，必要时在公式前面加负号。

4多模态融合 + 状态机

4.1 原理：先各自打分，再加权，再防抖

  1. 视觉分心分：头偏得越多、闭眼越多，扣分越多。
  2. 视觉疲劳分：PERCLOS 是主项，哈欠、长闭眼和异常的眨眼频率是加分项。
  3. 加权融合：视觉 0.7 + EEG 0.3（摄像头是真实实时的，所以权重更大）。
  4. EMA 平滑：y = y + k(x - y)，k=0.2 时大约相当于平均最近 5 次（2.5 秒）。
  5. 状态机：按优先级判定候选状态，候选需要持续 3 秒才切换，并且每个状态至少停留 5 秒。进入和退出用不同阈值（迟滞），避免在 60 分附近反复跳动。

const clamp = (v, lo = 0, hi = 100) => Math.max(lo, Math.min(hi, v));

export function fuse(eeg, face) {
  const offAxis = Math.max(clamp((Math.abs(face.yaw) - 15) * 4), clamp((-face.pitch - 10) * 5));
  const visFocus = clamp(100 - offAxis - face.perclos * 200);
  const blinkDev = Math.abs((face.blinkPerMin || 15) - 15);   // 前 60 秒按 15 次/分钟处理
  const visFatigue = clamp(face.perclos * 300 + face.yawns5min * 10 + face.longCloses * 10 + blinkDev);
  return {
    focus: 0.7 * visFocus + 0.3 * eeg.engagement,
    fatigue: 0.7 * visFatigue + 0.3 * eeg.drowsiness,
    present: face.present,
  };
}

export const ema = (prev, x, k = 0.2) => prev == null ? x : prev + k * (x - prev);

4.3 状态机 src/fusion/state.js

// 按优先级从上到下判定：先判断「人在不在」，再判断「困不困」，最后判断「专不专注」
const RULES = [
  { id: 'away',       enter: s => !s.present,       stay: s => !s.present },
  { id: 'drowsy',     enter: s => s.fatigue > 75,   stay: s => s.fatigue > 65 },
  { id: 'tired',      enter: s => s.fatigue > 55,   stay: s => s.fatigue > 45 },
  { id: 'distracted', enter: s => s.focus < 40,     stay: s => s.focus < 50 },
  { id: 'focused',    enter: s => s.focus > 70,     stay: s => s.focus > 60 },
  { id: 'normal',     enter: () => true,            stay: () => true },
];

export class StateMachine {
  constructor({ hold = 3000, minDwell = 5000 } = {}) {
    Object.assign(this, { hold, minDwell, state: 'normal', since: 0, cand: null, candSince: 0, listeners: [] });
  }

  onChange(fn) { this.listeners.push(fn); }

  update(s, now = performance.now()) {
    const cur = RULES.find(r => r.id === this.state);
    const higher = RULES.slice(0, RULES.indexOf(cur)).find(r => r.enter(s));
    const next = higher?.id ?? (cur.stay(s) ? this.state : RULES.find(r => r.enter(s)).id);

    if (next === this.state) { this.cand = null; return this.state; }
    if (next !== this.cand) { this.cand = next; this.candSince = now; }
    if (now - this.candSince >= this.hold && now - this.since >= this.minDwell) {
      const prev = this.state;
      Object.assign(this, { state: next, since: now, cand: null });
      this.listeners.forEach(fn => fn(next, prev, s));
    }
    return this.state;
  }
}

原理higher 这一行的意思是：优先级更高的状态可以随时「抢占」（比如正在专注时突然困了），而当前状态只要 stay 条件还成立就继续保持。

5.1 原理：Live2D 怎么动起来

/* Tanner Helland 色温→RGB 近似算法，适用于 1000–40000K */
static void kelvin_to_rgb(int k, uint8_t *r, uint8_t *g, uint8_t *b) {
    float t = k / 100.0f, R, G, B;
    R = t <= 66 ? 255 : 329.698727f * powf(t - 60, -0.1332047592f);
    G = t <= 66 ? 99.4708025861f * logf(t) - 161.1195681661f : 288.1221695283f * powf(t - 60, -0.0755148492f);
    B = t >= 66 ? 255 : (t <= 19 ? 0 : 138.5177312231f * logf(t - 10) - 305.0447927307f);
    *r = fminf(255, fmaxf(0, R)); *g = fminf(255, fmaxf(0, G)); *b = fminf(255, fmaxf(0, B));
}

static uint16_t rgb565(uint8_t r, uint8_t g, uint8_t b) {
    return ((r & 0xF8) << 8) | ((g & 0xFC) << 3) | (b >> 3);
}

/* ↓ 两个适配函数：按你手上例程 lcd.h 里的实际函数名改 */
static void ui_fill(uint16_t c) { lcd_clear(c); }
static void ui_text(int y, const char *s) { lcd_show_string(10, y, 220, 24, 24, (char *)s, BLACK); }

static void apply(const desk_cmd_t *c) {
    char line[40];

static void on_mqtt(void *arg, esp_event_base_t base, int32_t id, void *data) {
    esp_mqtt_event_handle_t e = data;
    if (id == MQTT_EVENT_CONNECTED) {
        esp_mqtt_client_subscribe(mqtt, "desk/cmd", 1);
        esp_mqtt_client_publish(mqtt, "desk/status", "online", 0, 1, 1);
    } else if (id == MQTT_EVENT_DATA) {
        cJSON *j = cJSON_ParseWithLength(e->data, e->data_len);
        cJSON *t = j ? cJSON_GetObjectItem(j, "type") : NULL;
        if (cJSON_IsString(t)) {
            desk_cmd_t c = { .kelvin = 4500, .level = 80 };
            strlcpy(c.type, t->valuestring, sizeof c.type);
            c.kelvin = jint(j, "kelvin", 4500); c.level = jint(j, "level", 80);
            c.step = jint(j, "step", 0); c.total = jint(j, "total", 0);
            cJSON *n = cJSON_GetObjectItem(j, "name");
            strlcpy(c.name, cJSON_IsString(n) ? n->valuestring : "-", sizeof c.name);
            if (c.kelvin < 1000 || c.kelvin > 10000) c.kelvin = 4500;   /* 边界校验 */
            if (c.level < 0 || c.level > 100) c.level = 80;
            xQueueSend(cmd_q, &c, 0);
        }
        cJSON_Delete(j);
    }
}

static void on_wifi(void *arg, esp_event_base_t base, int32_t id, void *data) {
    if (base == WIFI_EVENT && (id == WIFI_EVENT_STA_START || id == WIFI_EVENT_STA_DISCONNECTED)) esp_wifi_connect();
    else if (base == IP_EVENT && id == IP_EVENT_STA_GOT_IP) esp_mqtt_client_start(mqtt);
}

static void wifi_mqtt_init(void) {
    ESP_ERROR_CHECK(nvs_flash_init());
    ESP_ERROR_CHECK(esp_netif_init());
    ESP_ERROR_CHECK(esp_event_loop_create_default());
    esp_netif_create_default_wifi_sta();
    wifi_init_config_t cfg = WIFI_INIT_CONFIG_DEFAULT();
    ESP_ERROR_CHECK(esp_wifi_init(&cfg));
    esp_event_handler_register(WIFI_EVENT, ESP_EVENT_ANY_ID, on_wifi, NULL);
    esp_event_handler_register(IP_EVENT, IP_EVENT_STA_GOT_IP, on_wifi, NULL);
    wifi_config_t wc = { 0 };
    strlcpy((char *)wc.sta.ssid, WIFI_SSID, sizeof wc.sta.ssid);
    strlcpy((char *)wc.sta.password, WIFI_PASS, sizeof wc.sta.password);
    esp_wifi_set_mode(WIFI_MODE_STA);
    esp_wifi_set_config(WIFI_IF_STA, &wc);

        .broker.address.uri = BROKER_URI,

    };
    mqtt = esp_mqtt_client_init(&mc);
    esp_mqtt_client_register_event(mqtt, ESP_EVENT_ANY_ID, on_mqtt, NULL);

void app_main(void) {
    /* ← 这里放例程里原有的 LCD / XL9555 初始化 */
    cmd_q = xQueueCreate(8, sizeof(desk_cmd_t));
    gpio_config_t key = { .pin_bit_mask = 1ULL << GPIO_NUM_0, .mode = GPIO_MODE_INPUT, .pull_up_en = 1 };

        last = now;                                      /* 20 ms 轮询本身就起到消抖作用 */
    }
}

原理为什么用队列：esp-mqtt 的事件回调运行在它自己的任务里，如果直接在回调里刷屏，就会和主循环同时操作 SPI 总线。把「解析」和「执行」分到两个任务，用队列传递数据，是 FreeRTOS 的标准写法。

L3 的 sim/screen_gamma.py（订阅 desk/cmd，收到 light 就调整整块屏幕）：

import atexit
import ctypes
import json

import paho.mqtt.client as mqtt

gdi, user = ctypes.windll.gdi32, ctypes.windll.user32
hdc = user.GetDC(None)


def set_gamma(r, g, b):  # 0–1 的通道增益
    ramp = (ctypes.c_ushort * 256 * 3)()
    for i in range(256):
        for ch, gain in enumerate((r, g, b)):
            ramp[ch][i] = min(65535, int(i * 257 * gain))
    gdi.SetDeviceGammaRamp(hdc, ctypes.byref(ramp))


atexit.register(set_gamma, 1, 1, 1)  # 退出时一定要恢复


def on_message(client, userdata, msg):
    cmd = json.loads(msg.payload)
    if cmd.get("type") == "light":
        t = max(0.0, min(1.0, (6500 - int(cmd["kelvin"])) / 3800))  # 6500K=原色，2700K=最暖
        set_gamma(1.0, 1.0 - 0.15 * t, 1.0 - 0.45 * t)


client = mqtt.Client(mqtt.CallbackAPIVersion.VERSION2, client_id="screen-gamma")
client.on_connect = lambda c, *a: c.subscribe("desk/cmd")
client.on_message = on_message
client.connect("localhost", 1883)
client.loop_forever()

注意Windows 对 gamma ramp 的偏移幅度有限制，调得太狠时调用会静默失败（返回 0），上面的增益范围在限制之内。外接显示器和部分笔记本屏幕可能不支持。脚本异常退出、来不及恢复时，再运行一次 set_gamma(1,1,1) 即可复原。

  window.neuro = { player, features, sm, avatar };           // 方便在控制台调试，例如 neuro.player.seek(170)
